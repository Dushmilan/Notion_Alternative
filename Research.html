ArchBlueprint

Local-First Workspace

Executive Summary

This document details the architectural foundation for a high-performance, local-first, cross-platform (Windows/Android) workspace application. The system operates on a core philosophy of immediate startup times and offline capability, utilizing the user's personal Google Drive for cloud synchronization without relying on proprietary backend servers.

Through comprehensive analysis, this interactive report evaluates cross-platform UI frameworks, block-based rich text editors, conflict-free database syncing (CRDTs), and code structures optimized specifically for AI-assisted development paradigms.

1. Cross-Platform UI Frameworks

Evaluating Tauri v2, Flutter, and Kotlin Multiplatform (KMP) across memory footprint, rendering speed, and LLM-friendliness (availability of idiomatic training data). Higher scores (out of 10) are better.

Tauri v2 (Rust + TS)

Leverages OS-native webviews (WebView2 on Windows, System WebView on Android). Extremely small executable size. Excellent for AI-assisted development due to massive volumes of HTML/TS/React training data.

Flutter (Dart)

Brings its own rendering engine (Impeller/Skia). Guarantees pixel-perfect UI across desktop and mobile. Heavier memory footprint than Tauri, but exceptionally fast rendering. Moderate LLM context depth.

KMP + Compose

Compiles to native binaries. Unmatched Android performance, rapidly maturing desktop support. Syntax is concise, but Compose Multiplatform has less widespread AI training data compared to React/Web.

2. The Block-Based Editor Core

A Notion-like app requires granular blocks rather than standard markdown. We evaluate engines based on Extensibility, Out-of-the-box functionality, Mobile Support, and AI Context fit.

TipTap (ProseMirror based)

Headless, deeply extensible. Ideal for injecting custom CRDTs and relational DB links inline. High boilerplate required to get started.

BlockNote

Built on top of TipTap, highly optimized for "Notion-like" block UI out of the box. Excellent for rapid AI generation with minimal boilerplate.

Lexical (Meta)

Unmatched performance and DOM management. However, its complex state update paradigm can cause AI hallucination without massive prompt context.

Editor.js

Clean JSON output, true block architecture. Historically weaker on mobile touch interactions compared to ProseMirror-based solutions.

4. AI-Assisted Development Strategy

To prevent LLM context exhaustion, the architecture must strictly separate concerns. Monolithic files will cause AI to drop context and introduce bugs.

Recommended Folder Structure

src/
├── core/
│   ├── crdt/      [Yjs/Automerge logic]
│   ├── db/        [Local SQLite adapters]
│   └── sync/      [GDrive API workers]
├── editor/
│   ├── blocks/    [Custom Node definitions]
│   └── extensions/[Toolbar, commands]
├── ui/
│   ├── components/[Dumb UI, buttons]
│   └── views/     [Smart layout pages]
└── state/         [Zustand/Riverpod stores]

State Management Paradigm

  • Avoid React Context hell: Use atomic state managers (like Zustand for TS or Riverpod for Dart). LLMs can easily parse atomic store definitions.
  • Data Flow: UI components dispatch actions -> State updates local Yjs Doc -> Local DB listener saves to disk -> Sync worker queues delta for GDrive upload.
  • AI Prompting Tip: Because the logic is decoupled, you can prompt the AI to "Write a new Custom Block for the Editor" without feeding it any networking or database code.

5. Definitive Stack Recipes

Select a blueprint based on your target development experience and performance requirements.

The Web-Dev Familiar Stack

Maximizes speed of UI development utilizing massive LLM training data for React/Web ecosystems.

Frontend

Tauri v2 + React

Editor Engine

BlockNote (TipTap)

Local Database

SQLite (sql.js / tauri-plugin)

CRDT Layer

Yjs + y-sqlite

Sync Workflow:

  1. User types in BlockNote. Editor emits Yjs document updates (state vectors).
  2. Updates are flushed immediately to the local SQLite database via Tauri native Rust plugin.
  3. A background web worker chunks the Yjs state updates into binary blobs.
  4. Worker authenticates via Google Identity and uploads blobs to the hidden appDataFolder using Google Drive REST API.
  5. Other devices poll/sync appDataFolder, download new blobs, and apply Y.applyUpdate() to perfectly merge changes without conflicts.

The Bare-Metal Performance Stack

Maximizes raw performance, native compilation, and avoids browser webview overhead entirely. Harder for AI to write, but results in a premium native feel.

Frontend

Flutter (Dart)

Editor Engine

SuperEditor (Dart)

Local Database

ObjectBox (NoSQL)

CRDT Layer

CBL (Couchbase Lite) or Automerge-RS via FFI

Sync Workflow:

  1. User interacts with Flutter's SuperEditor. Custom block logic updates an ObjectBox local database entity.
  2. If utilizing Automerge via Rust FFI (Foreign Function Interface), changes are serialized into a highly compressed document delta.
  3. Flutter's Google Sign-In package requests `drive.appdata` scopes.
  4. The app securely uploads the binary deltas to Google Drive.
  5. ObjectBox's rapid read/write speeds allow for instant local startup, resolving the delta merges asynchronously in the background.
